# design-md-ui

以本仓库的 `awesome-design-md` 设计库为参考，**按实际需求**挑选并借鉴他人优秀 UI 的设计语言（配色逻辑、字体层级、间距节奏、组件处理），产出视觉一致、可复用、非"浏览器默认样式"的界面。核心是**择优借鉴 + 适配需求**，不是整站照搬某一套。

## 何时使用

- 新建页面 / 组件 / 小程序的视觉层（HTML、CSS、Tailwind、CSS-in-JS、Vue/React 组件样式）。
- 对已有界面做美化、改版、配色或排版调整。
- 用户给出风格关键词（如"做一个像 Linear 一样的产品页"）。

不适用：纯后端、算法、构建脚本、数据处理等与界面无关的任务。

## 设计库

- 位置：`awesome-design-md/design-md/<站点>/DESIGN.md`（共 84 套，均为真实网站的设计系统分析）。
- 索引：`awesome-design-md/README.md` 的 "Collection" 章节；本技能的 `references/catalog.md` 是中文精简选型清单。
- 文件格式：YAML frontmatter（`colors`、`typography` 两段令牌）+ Markdown 正文，正文固定九节：
  1. Visual Theme & Atmosphere（氛围与基调）
  2. Color Palette & Roles（颜色令牌 + 语义角色）
  3. Typography Rules（字体家族 + 完整层级表）
  4. Component Stylings（按钮 / 卡片 / 输入 / 导航及状态）
  5. Layout Principles（间距刻度、栅格、留白哲学）
  6. Depth & Elevation（阴影与表面层级）
  7. Do's and Don'ts（设计红线与反模式）
  8. Responsive Behavior（断点、触控目标、折叠策略）
  9. Agent Prompt Guide（速查色板 + 现成提示词）
- 部分文件无 frontmatter，同样以正文九节为准。

## 工作流

1. **定需求**：先写清本次界面的实际需求——产品类型、目标用户、信息密度、明 / 暗、品牌调性、要强调的核心动作。需求不清就先问用户或做合理假设并标注。
2. **选基准**：在 `references/catalog.md` 中按需求就近挑出 1 套作为**参考基准**；如需补充（例如基准偏暗但本项目要浅色、或想借其数据表格/空状态做法），再入选 1–2 套作为**局部参考**，明确主辅关系。
3. **读与提炼**：完整 `Read` 所选 `DESIGN.md`（不要只看 frontmatter），提炼出可复用的：配色逻辑与令牌、字体层级、间距刻度、圆角 / 阴影层级、组件与状态、Do's & Don'ts。记的是"为什么这么定"，不是"抄哪几个值"。
4. **建令牌**：把提炼结果落成一份集中定义（CSS 变量 / Tailwind theme / `tokens.ts`），并按本项目需求做必要调整（调整处写理由），全页面只引用令牌，禁止硬编码零散色值。
5. **实现**：按需求的层级与信息密度组织布局，套用令牌；响应式与触控目标按所选 `Responsive Behavior` 处理。
6. **自查**：对照 Do's & Don'ts 与需求逐条核对，确认"借鉴到位且适配自身"后再交付。

## 选型规则

- 以 1 套为**主基准**保证整体统一；仅当需要某类具体做法（图表、空状态、定价表、暗色反差等）时，才**局部借鉴**另一套，并沿用主基准的令牌体系，不混用两套色 / 字。
- 按行业 / 气质就近匹配，例如：开发者工具→Linear / Vercel / Cursor；AI 产品→Claude / Cohere / ElevenLabs；金融→Stripe / Mercury / Wise；电商零售→Shopify / Nike / Airbnb；媒体资讯→WIRED / The Verge；极简高端→Apple / Tesla。
- 完整 84 套按分类列于 `references/catalog.md`。

## 借鉴而非照搬

- 借鉴的是**设计语言与决策方法**：为什么用这个主色、层级如何拉开、留白如何控制、组件状态怎么处理。
- 必须**结合自身需求做取舍与改造**：不需要的元素删掉，不适配的品牌色 / 专有字体替换为等效的通用方案，并说明替换依据。
- 不得直接复刻他人品牌标识、商标、专有字体或受版权保护的图像等素材。
- 产出应让人看出"参考了成熟设计体系"，而不是"换了个 logo 的某个网站"。

## 落地硬性要求

- **颜色**：以主基准 DESIGN.md 的令牌为源，落到 CSS 变量或主题变量；如因需求替换品牌色，给出等效替代值并说明。
- **字体**：遵循其字体家族与层级表（字号 / 字重 / 行高 / 字距）；若为专有字体，替换为等效通用字体并保持层级比例。
- **间距 / 圆角 / 阴影**：使用其刻度值，保持节奏统一。
- **深色 / 浅色**：若 DESIGN.md 定义了 dark 表面，需同时给出对应实现。
- **无障碍**：保证正文对比度、可聚焦焦点样式与足够触控目标。
- **不臆造**：不得编造 DESIGN.md 中不存在的色值或字体；确需补充时，显式标注为"扩展值"并说明依据。

## 交付自检

交付前确认：
- [ ] 已说明本次界面需求，并据此选定主基准（必要时标注局部参考）；
- [ ] 已完整阅读所选 DESIGN.md 并提炼出令牌与原则；
- [ ] 颜色 / 字体 / 间距 / 圆角 / 阴影可追溯到所选令牌，替换处已说明理由；
- [ ] 无浏览器默认样式残留，无随手硬编码色值，未整站照搬也未混用两套令牌；
- [ ] 已逐条核对 Do's & Don'ts；
- [ ] 已按 Responsive Behavior 处理响应式与触控目标。
